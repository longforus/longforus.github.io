📝 问题背景

在 CachyOS (基于 Arch Linux) 等滚动发行版中，系统升级（特别是 systemd 升级）后，原本通过 udev 规则直接执行硬件控制脚本（如 ddcutil）可能会失效。

失效原因：

  1. 沙箱限制加严：新版 systemd-udevd 引入了严格的后台沙箱，禁止直接在 Udev 的 RUN 指令中访问 /dev/i2c-* 等硬件接口，导致命令被静默拦截。
  2. 环境变量缺失：ddcutil 在无头 (Headless) 环境下执行时，找不到 $HOME 变量，无法定位并读取 dynamic sleep cache 缓存文件，从而报错退出或执行极慢。

标准架构（最佳实践）：

USB 拔插事件 ➜ Udev 规则 ➜ 触发 Systemd Service ➜ 执行 Bash 脚本 ➜ ddcutil (指定 Bus)

🔍 未来排查指南 (Troubleshooting)

如果日后再次失效，请严格按照以下 “从上到下” 的顺序进行二分排查：

第一步：测试最底层的 ddcutil 和脚本

手动执行脚本，看显示器是否切换：

Bash

  • 如果正常切换：进入第二步。

第二步：测试 Systemd 服务层

手动触发 Systemd 服务：

Bash

  • 如果失败：查看报错日志：

    Bash

  • 如果正常切换：说明服务正常，问题出在最前端的 Udev，进入第三步。

第三步：测试 Udev 监听层

查看 USB 设备拔插时的真实 ID 和环境变量：

Bash

拔插设备，观察弹出的日志，检查下面三个变量是否发生变化：

  • ACTION（是 remove 还是 unbind？）

  • PRODUCT（设备 ID 是否还是 152a/85dd/xxx 格式？）

    如果发生了变化，同步修改 /etc/udev/rules.d/99-usb-dac.rules 中的匹配条件即可。
